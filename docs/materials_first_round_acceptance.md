# 材料链第一轮修复与外部验收

日期：2026-10-22。范围：产品根目录的材料链、SOP 票据接入和正式 CLI。

## 已修复的行为

1. **语义问题定点复审**：独立审计的开放 P0/P1 不会因为修改字数少而由
   `wording_only_lint` 自动关闭。修复后返回 `incremental_repair` 任务，携带原
   finding、目标块和问题类别。原问题保持开放，直到独立结果回来。首次审计前
   的 repair 仍要求完整首审。三审和重复 finding 熔断继续有效。
2. **减少跨雇主误报**：词项归属使用真实 experience ID；通用职位/团队词不作为
   雇主专属标识；母版中已有的组织引用不因措辞定制被当成新增泄漏。
3. **岗位任务授权**：首次材料票据向用户说明两小时内的岗位任务范围。兑换后，
   后续常规阶段由宿主签发并兑换新的一次性票据，模型无需逐步拼接 secret。
   授权绑定 workspace、岗位、包和 generation。重置、用户事实确认、accept/dispute、
   浏览器抓取、其他岗位与真正投递不在范围内。到期或 generation 改变后重新授权。
4. **完整恢复指引**：未知公司身份返回固定 request/response 路径和可执行提交命令；
   `materials company-research` 只消费当前包的响应，身份带来源核验后可继续。已有冻结
   bundle 的公司身份不能被静默改写。`materials audit/format` 是顶层同名门的别名。
5. **解释器与锚点引导**：系统 Python 启动 CLI 时优先转入项目已安装的 `.venv`；
   已激活的合格虚拟环境保持不变。planning 阶段的种子锚点明确标为 `awaiting_plan`，
   不再被描述成实际抽取的 JD 要求。

## 交给外部模型时

使用之前的“首次接触项目，制作指定编号材料，并提交验收报告”任务即可。
选择一个尚未制作过材料、有完整 JD 的岗位。不需要向执行模型解释这些内部实现。
如选择已有成品的岗位，重置仍须由用户明确确认。

执行模型仅进行求职业务操作，不修改产品代码、状态、哈希或审计回执来排障。

## 本轮重点观察

- 首次授权卡是否明确展示岗位及范围；正常后续阶段是否不再要求手工交换票据。
- 公司身份不完整时，是否能按 recovery 指引提交，无需阅读源码或参考其他岗位。
- 独立首审发现语义 P1 后，修复是否产生定点复审；最终记录是否准确反映独立结果。
- 不要求审计必须发现问题；无问题的首审可以正常通过。需要审计时也不得冒充子 Agent。
- 是否只修改相关内容，保持已有合格产物和正常的渲染链。
- 页数、文本层、文件名、元数据及最终产物检查是否照常运行；仍不自动投递。
