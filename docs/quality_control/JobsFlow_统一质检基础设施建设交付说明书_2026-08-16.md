## 1. 项目背景与建设原则

JobsFlow 是一个本地优先、大模型参与执行的求职工作流系统。在引入多模型、不同模型能力梯队及中途模型热切换的场景下，系统需要一套严格的质量控制基础设施以回答以下核心问题：

1. **流程合规性**：模型是否严格按照 JobsFlow 统一 Gateway 入口与 SOP 执行？
2. **状态与副作用安全**：是否发生非法状态跃迁、未经确认的数据写入或跨目录越权？
3. **模型可替代性**：更换模型后，是否仍能稳定完成同一阶段的任务？
4. **材料内容质检**：生成的 CV/CL 是否满足 STAR 原则、LLMO 证据排序与去模板化要求？
5. **故障可回溯性**：任务失败后，能否精准定位断点、模型责任并支持无损断点恢复？

### 建设与隔离原则
- **分层隔离**：`quality_control/` 核心库保持业务无关；产品只通过一个桥接模块观察真实网关结果，不复制工作流；
- **私人空间绝对隔离**：严禁读取、写入或索引 `JobSearch_2026/` 私人实例；
- **纯合成数据验证**：所有测试与 Fixture 100% 使用脱敏合成数据，杜绝真实 PII；
- **零外部 API 强依赖**：核心库基于 Python 标准库构建，在无网络与无外部 API Key 环境下保持 100% 可测试性。

## 2. 总体架构与分层设计

质检基础设施采用分层解耦架构，保证核心评测逻辑独立于 JobsFlow 业务细节与第三方外部平台：

```text
               ┌────────────────────────────────────────────────────────┐
               │         合成任务案例库 / 多模型准入评测矩阵            │
               └──────────────────────────┬─────────────────────────────┘
                                          │
                                          ▼
               ┌────────────────────────────────────────────────────────┐
               │          Quality Runner (合成准入评测引擎)             │
               └──────┬───────────────────┬──────────────────────┬──────┘
                      │                   │                      │
       ┌──────────────┴───────┐ ┌─────────┴────────────┐ ┌───────┴───────────────┐
       │   Adapters Layer     │ │   Evaluators Layer   │ │ Observability Layer   │
       ├──────────────────────┤ ├──────────────────────┤ ├───────────────────────┤
       │ • FakeJobsflowAdapter│ │ • Deterministic SOP  │ │ • LocalJsonlSink      │
       │ • FakeModel (多形态) │ │ • Semantic (CV/CL)   │ │ • TraceManager (度量) │
       │ • Promptfoo (可选)   │ │ • FormatGate (机械门)│ │ • ReplayEngine (回放) │
       │ • Inspect AI (可选)  │ │ • Takeover (接管评估)│ │ • InMemorySink        │
       │ • DeepEval (可选)    │ └──────────────────────┘ └───────────────────────┘
       └──────────────────────┘
                                          │
                                          ▼
               ┌────────────────────────────────────────────────────────┐
               │  Assertion Results ──► Verdict ──► Report / Replay     │
               └────────────────────────────────────────────────────────┘
                                      ▲
                                      │  product-side observer
                         tools/workflow/quality_control_bridge.py
                                      ▲
                                      │
                         WorkflowEngine / unified gateway
```

### 目录组织结构

## 3. 核心数据契约与数据模型

所有数据实体均具备对应的严格 JSON Schema 校验（位于 [`quality_control/schemas/`](file:///Users/xiezhijie/ai-job-search/quality_control/schemas/)），缺失必要字段时强制 **Fail-Closed**。

### 3.1 模型描述符 (`ModelDescriptor`)
用于描述参与执行的大模型元数据与运行时配置：
```json
{
  "provider": "anthropic",
  "model_id": "claude-3-7-sonnet",
  "harness": "cli|api|desktop|synthetic",
  "model_version": "2026-08",
  "capability_profile": "strong_reasoning",
  "temperature": 0.2
}
```

### 3.2 工作流事件 (`WorkflowEvent`)
记录系统状态迁移、模型交互与审计全过程的标准事件：
```json
{
  "run_id": "qa-20260816-0001",
  "event_id": "evt-3f8a1c90",
  "event_type": "run_started|stage_started|stage_completed|stage_blocked|model_invoked|model_switched|artifact_created|audit_started|audit_completed|reset_requested|run_completed",
  "timestamp": "2026-08-16T12:00:00Z",
  "stage": "materials",
  "source": "gateway|child_auditor|host_compiler",
  "data": {},
  "input_hash": "sha256:...",
  "output_hash": "sha256:...",
  "error_code": null
}
```

### 3.3 断言结果 (`AssertionResult`)
机器可读的结构化评估输出：
```json
{
  "assertion_id": "SOP-001",
  "category": "state|sop|artifact|side_effect|semantic|performance",
  "severity": "P0|P1|P2|info",
  "status": "pass|fail|skip|not_applicable",
  "message": "Unified gateway entry point verified",
  "evidence": ["source=gateway"],
  "remediation": "",
  "blocking": false
}
```

### 3.4 模型接管包与握手协议 (`HandoffPacket` & `TakeoverAck`)
在任务中途切换模型时，生成自洽的上下文交接包：
- **`HandoffPacket`**：冻结当前阶段、任务哈希、草稿哈希、未解决 Finding 列表、允许动作与禁止动作；
- **`TakeoverAck`**：新模型必须显式确认阶段、理解未解决问题，并声明下一步合规动作，否则系统终止执行。

## 4. 核心评测引擎实现

基础设施构建了四大独立评测器，覆盖从机械门到语义审查的完整链条：

### 4.1 确定性 SOP 评估器 ([`DeterministicEvaluator`](file:///Users/xiezhijie/ai-job-search/quality_control/evaluators/deterministic.py#L24))
无需调用 LLM，秒级完成硬规则校验：
- **`SOP-001` (网关入口)**：强制所有调用必须走 `python3 -m tools.workflow`，拦截绕过网关的直接脚本调用；
- **`STATE-001` (状态顺序)**：严格遵循 `setup → scan → push → materials → apply` 时序，拦截未重置的非法回跳；
- **`SOP-002` (扫岗解耦)**：严禁在 `/scan` 阶段生成任何材料产物（DOCX/PDF/CV）；
- **`SOP-003` (推送确认)**：严禁在未经用户明确确认的情况下直接写入 Tracker 账本；
- **`SOP-005` (计划优先)**：材料制作阶段必须先生成并校验 Plan，再提交 Draft 变换；
- **`SOP-007` & `SOP-008` (审计轮次与熔断)**：强制审计轮次不超过 3 轮；连续两次出现相同 Finding 自动触发 `audit_loop_detected` 熔断；
- **`PRIVACY-001` (隐私隔离)**：拦截任何指向 `JobSearch_2026/` 的未授权读写。

### 4.2 材料文字语义评估器 ([`SemanticContentEvaluator`](file:///Users/xiezhijie/ai-job-search/quality_control/evaluators/semantic.py#L42))
专注于 CV 与 Cover Letter 的纯文本质量审查（不负责排版与 PDF）：
- 检查是否存在 `[Company Name]`、`{{...}}`、`TODO:`、内部提示词或审计残留标记；
- 检查是否存在空泛不实的夸张吹捧词汇（如 "world-renowned leader in excellence"）；
- 检查是否存在候选人主动暴露未要求缺陷的不利表述；
- 验证职位名称、雇主名称与机构身份描述的中性合规性。

该评估器主要服务合成准入和通用卫生检查；生产材料的 STAR、JD 映射、LLMO 位置和独立复核继续由
`tools/workflow/materials_vnext` 的 CV/CL 子审计负责，产品桥不会再派第二个语义 Agent。

### 4.3 机械格式门评估器 ([`FormatGateEvaluator`](file:///Users/xiezhijie/ai-job-search/quality_control/evaluators/format_gate.py#L21))
针对最终渲染产物的机械硬门检查：
- 严格限制 CV 为 1 页，Cover Letter 为 1 页；
- 校验 DOCX 与 PDF 是否成对生成，且由统一渲染器产出；
- 拦截空文件、异常文件大小或错误目录产物。

生产运行不使用此合成评估器替代 JobsFlow 的 renderer；桥接层只读取现有 `mechanical_format_gate` 报告。

### 4.4 模型接管评估器 ([`TakeoverEvaluator`](file:///Users/xiezhijie/ai-job-search/quality_control/evaluators/takeover.py#L21))
- 校验模型交接包 (`HandoffPacket`) 的完整性与哈希一致性；
- 校验接管确认 (`TakeoverAck`)，严禁新模型执行已完成历史阶段或越权动作。

## 6. 可观测性、度量与回放体系

### 6.1 本地 JSONL 跟踪 ([`LocalJsonlSink`](file:///Users/xiezhijie/ai-job-search/quality_control/observability/sinks.py#L22))
所有工作流事件与运行总结均实时脱敏并持久化至本地 `.jsonl` 文件中。每条记录均打上 `_record_type` 标签（`event` 或 `run_record`），支持按 `run_id` 精确检索。

### 6.2 细粒度性能与资源度量 ([`TraceManager`](file:///Users/xiezhijie/ai-job-search/quality_control/observability/trace.py#L13))
系统分别独立统计各项指标，避免将所有耗时笼统归咎于“模型慢”：
- **`model_duration_ms`**：大模型调用与推理耗时；
- **`qa_duration_ms`**：本地确定性规则、Schema 校验与质检耗时（毫秒级）；
- **`external_duration_ms`**：外部网络请求耗时；
- **`tokens_used`**：单次任务消耗的总 Token 数；
- **`retry_count`** / **`rework_cycles`**：模型重试与材料返工轮次。

### 6.3 确定性回放引擎 ([`ReplayEngine`](file:///Users/xiezhijie/ai-job-search/quality_control/observability/replay.py#L48))
可将任意一次成功或失败的运行导出为单文件 [`ReplayBundle`](file:///Users/xiezhijie/ai-job-search/quality_control/observability/replay.py#L14)，回放引擎能够对其进行时间线一致性检验，并在测试环境中离线复现当时的完整事件序列。

## 7. CLI 命令行工具使用手册

质检基础设施提供开箱即用的命令行工具：

```bash
# 1. 运行指定用例
python3 -m quality_control run --case materials_happy_path_001 --model fake-happy

# 2. 运行违规反例（验证阻断能力）
python3 -m quality_control run --case plan_missing_002 --model fake-plan-missing

# 3. 指定输出报告路径与 Trace 存储位置
python3 -m quality_control run --case materials_happy_path_001 --output /tmp/run_report.json --trace-log /tmp/traces.jsonl

# 4. 运行模型准入评测矩阵（对比多模型表现）
python3 -m quality_control matrix

# 5. 查看历史运行记录
python3 -m quality_control report --trace-log .qc_traces/traces.jsonl

# 6. 回放指定的 ReplayBundle
python3 -m quality_control replay --file .qc_traces/replay_bundle.json

# 7. 基础设施健康自检
python3 -m quality_control check
```

自动化安全测试套件 ([`test_security_boundary.py`](file:///Users/xiezhijie/ai-job-search/tests/quality_control/test_security_boundary.py)) 静态与动态验证了以下安全约束：

1. **源码无私有路径引用**：`quality_control/` 源码中绝无直接硬编码指向 `JobSearch_2026/` 的读写逻辑；
2. **Fixture 无真实 PII**：所有用例中的姓名、邮箱、电话和经历均为合成脱敏数据；
3. **敏感凭证深度脱敏**：`Sanitizer` 确保 Bearer Token、API Key、Session Cookie、URL 认证参数均在进入日志前被替换为 `<REDACTED_*>`；
4. **私人实例隔离**：桥接只使用调用方传入的 workspace，源码不硬编码或索引 `JobSearch_2026/`；QC trace 默认落在该 workspace 的 workflow 目录。

## 9. 未来产品接入与灰度路线

基础设施已交付，产品侧接入由 `tools/workflow/quality_control_bridge.py` 完成；核心评测器仍可独立运行合成准入矩阵。

### 9.1 Feature Flag 灰度控制
```text
┌──────────┐      ┌───────────┐      ┌──────────┐      ┌───────────┐
│   off    │ ──►  │  observe  │ ──►  │   warn   │ ──►  │  enforce  │
│ (不运行) │      │ (静默记录)│      │(输出警告)│      │(硬门阻断) │
└──────────┘      └───────────┘      └──────────┘      └───────────┘
```

- **`off`**：完全不启用质检；
- **`observe`（推荐第一阶段）**：主链各阶段触发 `WorkflowEvent` 发送至 `LocalJsonlSink`，记录日志但不阻断流程（建议在真实日常任务中观察 20~50 次）；
- **`warn`**：当质检器发现 P1/P2 问题时在控制台输出警告提示；
- **`enforce`（最终阶段）**：对 P0 违规（如漏 Plan、未经确认 Push）和材料泄露执行强制中断。

当前实现的 `enforce` 只阻断 adapter 执行前可确定且无副作用的 P0 请求；已有 gateway policy、vNext CV/CL 子审计和机械格式门继续是生产真源。QC 不派第二个材料审计 Agent，不读取 Email/PDF 正文，也不重写 DOCX。

### 9.2 接入点清单
1. **Gateway 阶段进入与完成**：触发 `run_started`, `stage_started`, `stage_completed`；
2. **Push 确认拦截点**：用户确认前拦截未授权写操作；
3. **Materials 编译与审计点**：在 TaskPacket 生成与 CV/CL 审计完成后输出事件；
4. **Renderer 产物落盘点**：在 DOCX/PDF 渲染完成后触发机械格式检查。

### 9.3 已实现的真实接入

- `WorkflowEngine.execute` 在 adapter 前调用 QC preflight；仅 `enforce` 且发现安全 P0 时阻断。
- `_audit` 将真实 action/result 映射为脱敏 QC 记录；`observe` 与 `warn` 不改变状态和副作用。
- `materials`、`audit`、`format`、`apply` 强制标记 vNext；QC 只验证 vNext 绑定、CV/CL audit scope、现有 format report 和 `/apply` 不提交。
- 产品集成测试使用真实 `dispatch()` 与合成 workspace，而不是 `FakeJobsflowAdapter`。
